## 1. Общий контекст и глобальное видение

Игра развивается в сторону **сессионной стратегии/RPG с 7-дневным циклом (Tug of War / Tower Defense)**:
- Две фракции: **Свет** (Замок Света: `-2000, -1000`) и **Тьма** (Цитадель Тьмы: `+2000, +1000`).
- Главный Тракт связывает замки, по нему каждые **4 часа** (уменьшается казармами до 2 часов) выходят **марширующие армии мобов**.
- Подробный утвержденный диздок находится в: `docs/GLOBAL_WAR_DESIGN.md`.

## 2. Зона ответственности Оператора 2

Как главный по боевой части, ты полностью контролируешь:
1. **Боевую логику персонажей и классов** (`combat/`):
   - Воины (`fighter.py`), лучники, маги (`mage.py`), карты способностей и магии (`spells.py`).
2. **Формат боев 3 на 3**:
   - Строгий лимит арены: не более 3 бойцов с каждой стороны.
   - Поддержка входа союзников в активный бой (дозаполнение свободных слотов до 3 игроков).
3. **Реал-тайм мир vs Пошаговый бой**:
   - Мир движется в реальном времени; бой идет в изолированной сессии `BattleSession`.
   - Таймер хода: 15–20 секунд на раунд с автоматическим ходом при пропуске времени.
4. **Быстрая автосимуляция «Бот vs Бот»**:
   - Когда армии мобов или нейтралы сталкиваются на карте без игроков — исход рассчитывается за 2-3 секунды без открытия окна пошагового боя.
5. **Механика «Авангард / Перехват марширующей армии»**:
   - Армия на карте — один юнит со счетчиком (например, `[Орда Тьмы: 24]`).
   - Игрок нападает $\rightarrow$ армия останавливается, игрок дерется с передовой тройкой (1x3).
   - При убийстве моба счетчик армии уменьшается, из резерва выходит следующий боец.
   - Если игрок погиб, остаток армии продолжает марш к городу.
6. **Баланс экипировки мобов**:
   - Зависимость характеристик солдат волны от развития городской кузницы (дубины $\rightarrow$ мечи) и мастерской (кожа $\rightarrow$ латы).

## 3. Общая база данных и финансовая система

**ВАЖНО**: База данных полностью общая для всех игроков на всей карте!

### Что хранится на сервере:
- 💰 Деньги (медь, серебро, золото) - ЕДИНЫЕ для всех игроков
- 🎒 Инвентарь - персональный по персонажу
- 🏪 Предметы в магазинах - ОБЩИЕ для всех
- 📊 Статистика боев - видна всем
- 💬 Чат по локациям - ЕДИНЫЙ для всех на одной локации

### Что означает это:
- Маг, который заработает 100 серебра в лесу → эти деньги видны боевому персонажу
- Боевик, который купит зелье у NPC → маг тоже видит что его нет
- **Клиент это только UI, все данные на сервере!**

## Структура кода для Mage разработки

### 1. Сцены (Локации)
```
scenes/
├── academy/           # Школа магии (аналог Tavern для магов)
│   ├── academy_scene.py
│   └── ...
├── magical_forest/    # Лес магии (аналог Backyard для магов)
│   ├── forest_scene.py
│   └── ...
```

**Шаблон**: Посмотри на `scenes/tavern_scene.py` и `scenes/backyard_scene.py` - магические локации должны иметь аналогичную структуру.

### 2. Боевая система
```
combat/
├── mage.py           # Логика боя для магов (аналог fighter.py)
└── spells.py         # Система магии
```

**Важно**: `fighter.py` использует stats: strength, agility, intuition
**Для магов**: используй stats: wisdom, spirituality

Посмотри как создается боец:
```python
# В database.py создание персонажа Mage:
if profession_type == "mage":
    stats = {
        "wisdom": 3,
        "spirituality": 3,
        "endurance": 4,  # НИКОГДА не повышается при левелапе!
    }
```

### 3. API эндпоинты
```
/api/mage/spells         - список доступных заклинаний
/api/mage/cast           - кастовать заклинание
/api/mage/meditate       - восстановление маны
/api/mage/*/academy      - действия в школе магии
/api/mage/*/forest       - действия в лесу магии
```

## Важные правила

### ❌ НЕЛЬЗЯ делать
- Создавать отдельную БД для магов
- Менять структуру таблицы `characters` без согласования
- Использовать хардкод для ID боевиков (всегда проверяй `character['type']`)
- Хранить данные в клиенте - всё идет на сервер!

### ✅ НУЖНО делать
- Проверять `character['type']` перед использованием боевой логики
- Все данные читать/писать через сессию
- Расширять API, не ломая существующие эндпоинты
- Использовать одну финансовую систему

   - Обнови `main.py` чтобы загружал academy вместо tavern для магов
