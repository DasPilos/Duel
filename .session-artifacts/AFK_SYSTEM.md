# АФК система (Away From Keyboard)

## Описание

АФК система предотвращает игроков от избегания боев путем закрытия клиента. Когда игрок отключается во время боя, его персонаж остается на сервере и продолжает участвовать в боевой последовательности.

## Архитектура

### База данных

Добавлена таблица `active_battles`:
- `id` - уникальный идентификатор боя
- `player_id` - ID персонажа игрока
- `opponent_id` - ID противника
- `battle_data` - JSON с состоянием боя (сохраняется при каждом ходу)
- `player_afk` - флаг АФК статуса игрока (1/0)
- `opponent_afk` - флаг АФК статуса противника (1/0)
- `created_at` - время создания боя
- `updated_at` - время последнего обновления

### Компоненты

1. **database.py** - методы для работы с состоянием боя:
   - `save_active_battle()` - сохраняет или обновляет состояние боя
   - `mark_player_afk()` - отмечает игрока как АФК
   - `get_active_battle()` - восстанавливает сохраненное состояние
   - `delete_active_battle()` - удаляет завершенный бой

2. **server/afk_battle.py** - логика АФК персонажа:
   - `AFKBattleManager` - выбирает случайные действия (карты, атаки)
   - `AFKBattleHandler` - управляет состоянием АФК в боях

## Поток выполнения

### При отключении клиента

1. Клиент закрыт → WebSocket соединение разорвано
2. Сервер обнаруживает потерю соединения
3. `disconnect()` срабатывает в `duel_scene.py`
4. Если `phase != "result"` - игрок остается подключен к серверу
5. Персонаж отмечается как АФК
6. Боевое состояние сохраняется в БД

### Во время АФК

1. Серверная система боя продолжает работать
2. На каждый ход АФК персонажа сервер выбирает действие:
   - Выбирает случайную карту из руки
   - Выбирает случайную зону атаки
   - Применяет действие в боевую систему
3. Боевое состояние обновляется в БД
4. Противник получает обновления о действиях АФК персонажа

### При переподключении

1. Игрок переподключается с тем же токеном
2. Система обнаруживает активный бой в БД
3. Полное состояние боя восстанавливается
4. Игрок видит экран боя в текущем состоянии
5. Статус АФК убирается, игрок может продолжить управление

### При завершении боя

1. Боевая система определяет победителя
2. XP и награды применяются к обоим персонажам
3. Статистика боя сохраняется в архив
4. Запись о боевом сеансе удаляется из `active_battles`
5. При переподключении игрок видит экран результатов

## Стратегии АФК действий

### Текущая: Случайная (random)

- Выбирает случайную карту из доступных
- Выбирает случайную зону атаки (front/center/back)
- Простая и непредсказуемая для противника

### Будущие: 

- **Aggressive** - приоритет карт с высоким уроном
- **Defensive** - приоритет карт с защитой/регенерацией
- **Strategic** - анализирует состояние боя и выбирает оптимальные действия

## Особенности

### НЕ реализовано (по требованиям пользователя)

- АФК персонаж НЕ может восстанавливать HP во время боя
- АФК персонаж берет урон как обычный персонаж
- АФК персонаж берет ходы в нормальном порядке (не ускоренные)

### Сохраняется при АФК

- HP персонажа
- Статус эффектов (баффы/дебаффы)
- Текущая рука карт
- Состояние колоды
- Информация о противнике

## Интеграция с фронтенд

### Сценарий 1: Бой продолжается, клиент переподключился

```
1. Клиент отправляет '/duel/status' с id противника
2. Сервер возвращает сохраненное состояние боя + флаг is_afk
3. Фронтенд восстанавливает сцену боя в том же состоянии
4. Показывает сообщение "Переподключение успешно, вы вернулись в бой"
5. Игрок может продолжить участвовать
```

### Сценарий 2: Бой завершился во время отключения

```
1. Клиент переподключается
2. Сервер возвращает результаты боя (победа/поражение)
3. Фронтенд показывает экран результатов
4. Игрок видит нанесенный/полученный урон, XP
5. Может вернуться в таверну
```

## Конфигурация

Добавьте в `server/config.py`:

```python
# АФК система
AFK_BATTLE_TIMEOUT_SECONDS = 300  # Как долго хранить бой (5 мин)
AFK_ACTION_DELAY_SECONDS = 3      # Задержка между действиями АФК
```

## Тестирование

### Проверка сохранения боя

```bash
# 1. Начните бой между двумя игроками
# 2. Выполните несколько ходов
# 3. Закройте клиент одного игрока
# 4. Проверьте БД:
SELECT * FROM active_battles WHERE player_id = <id>;
# Должно быть записано состояние боя в battle_data и player_afk=1
```

### Проверка восстановления

```bash
# 1. Переподключитесь с тем же клиентом
# 2. Бой должен продолжиться в том же состоянии
# 3. АФК персонаж должен выполнить действие
```

## Ошибки и их решение

| Проблема | Решение |
|----------|---------|
| Бой не восстанавливается | Проверьте, что character_id совпадает в `active_battles` |
| АФК персонаж не делает ходы | Убедитесь, что боевая система проверяет флаг `player_afk` |
| Данные боя потеряны | Проверьте TTL таблицы и периодическую очистку |
| Оба игрока АФК | Система должна продолжить бой, но в идеале нужна проверка таймаута |
