# Переход клиента оператора 2 с Python на Godot

Документ для оператора 2 и его ИИ-агента. Сервер общий и не меняется. Меняется только клиент: вместо Pygame-клиента (`main.py`) используется Godot-клиент (`godot_client/`).

Пути ниже даны для машины владельца проекта. На машине оператора 2 используйте свой путь к папке проекта: в тексте он обозначен как `<папка-проекта>`.

## 1. Коротко

1. Сервер (центральный и игровые миры) не переписывается. Он один и тот же для Python- и Godot-клиента.
2. Godot-клиент уже совместим с сервером: версия клиента `1.0.0`, протокол `1`, совпадают с сервером (`godot_client/scripts/api_client.gd`, `server/build_info.py`).
3. Godot-клиент проверяет совместимость перед входом и не пускает при несовпадении. Python-клиент версию не передаёт и не проверяется.
4. Front Line доступен только в Godot-клиенте. Python-клиент его не поддерживает.
5. Python-клиент не удаляйте. Пока держите его как резерв, пока не проверено, что все нужные функции работают в Godot.

## 3. Что есть в каждом клиенте

| Режим или функция | Python (`main.py`) | Godot (`godot_client/`) |
|---|---|---|
| Вход, аккаунт, лобби и чат | да | да (`main.gd`, `lobby_*.gd`, `lobby_chat_panel.gd`) |
| Tower: карта мира, бой в реальном времени | да (`scenes/world_map_scene.py`) | да (`world_entry.gd`, `tower_entity_view.gd`) |
| Front Line: драфт, волны, таверна | **нет** | да (тот же `world_entry.gd`) |
| Economy: город, склады, производство, замок, конюшня | да (`scenes/city/`, `scenes/town/`, `ui/`) | да (`economy_world.gd`, `economy_*.gd`) |
| Deck | да (пакет `deck/`) | да (`deck_world.gd`, `deck_*.gd`) |
| Создание персонажа | да (`create_character_scene.py`) | да (`create_character_view.gd`) |
| Редактор карт (модераторы) | да (`map_editor_scene.py`) | да (`map_editor.gd`, `map_editor_*.gd`) |
| Проверка версии перед входом | нет | да (`main.gd`, `/api/version`) |

Соответствие по имени файлов, а не по поведению. Перед отключением Python-клиента проверьте каждую функцию вручную. Особенно это касается таверны (`tavern_scene.py`) и присутствия AFK (`ui/afk_presence.py`): однозначного аналога в Godot-модулях я не нашла.

## 4. Порядок действий оператора 2

### Шаг 0. Резервная копия

- Скопируйте всю папку проекта в другое место. Не удаляйте ничего, пока не проверите Godot-клиент.
- Сохраните локальные черновики редактора карт `map_drafts/`. Серверу они не известны (`docs/server.md`).
- Папку `.venv`/`.venv_313` копировать не нужно, их создаёт установка зависимостей.

### Шаг 1. Получить код

1. Клонируйте ветку `integration/two-operators-2026-11-04` в новую папку (раздел 2) или получите копию от владельца, затем скопируйте арт `godot_client/assets/base_tails/`.
2. В папке проекта выполните:
   ```powershell
   git status
   git log --oneline -3
   ```
3. Не выполняйте `git reset --hard`, `git checkout .` и `git clean -fd`. Они удаляют незакоммиченные изменения.
4. Если ваши локальные изменения мешают, сначала сохраните их в отдельную ветку или архив и спросите владельца.

### Шаг 2. Установить Godot 4.7.1

- Нужна версия **4.7.1 stable, Windows 64-bit**. Проект проверялся именно на ней.
- Для запуска сцен из терминала используйте консольный исполняемый файл (`..._console.exe`).
- Откройте `godot_client/project.godot` в Godot. Главная сцена: `res://scenes/main.tscn`.

### Шаг 3. Python и зависимости

Серверам и тестам нужен Python 3.13 или новее:

```powershell
python -m pip install -r requirements.txt
```

Godot-клиенту Python для игры не нужен. Нужен только для серверов, миграций и Python-тестов.

### Шаг 4. PostgreSQL

- Серверы подключаются к PostgreSQL по `DATABASE_URL` (`server/config.py`). Пароли не записывайте в код и документы (`AGENTS.md`).
- Тесты используют `TEST_DATABASE_URL`. Укажите отдельную одноразовую базу, а не рабочую.

### Шаг 5. Запустить серверы в правильном порядке

1. Центральный сервер первым, на `127.0.0.1:8765`:
   ```powershell
   $env:HOST = '127.0.0.1'; $env:PORT = '8765'
   python -m server.central_main
   ```
2. Проверить: `http://127.0.0.1:8765/health` должен отвечать.
3. Игровые миры запускаются отдельными процессами (`tower.server.main`, `economy.server.main`, `deck.server.main`) с собственными `WORLD_ID`/`PORT`. Front Line центральный сервер создаёт и поддерживает сам (`godot_client/README.md`, раздел Front Line).
4. Проверить совместимость клиента с сервером:
   ```
   http://127.0.0.1:8765/api/version?app=client&version=1.0.0&protocol=1
   ```
   В ответе поле `compatibility.compatible` должно быть `true`.

Если сервер уже работает, после обновления кода его нужно перезапустить по правилам `AGENTS.md`: сначала центральный сервер, затем миры. Останавливайте только точные PID старых процессов.

### Шаг 6. Запустить Godot-клиент

1. Откройте `godot_client/project.godot` и нажмите F5.
2. В поле адреса введите `http://127.0.0.1:8765` (или адрес сервера, которому вы доверяете).
3. Клиент сам проверит `/api/version`. Если версия или протокол не совпадают, вход заблокирован и показывается сообщение о несовместимости (`godot_client/scripts/main.gd`).
4. Войдите в существующий аккаунт или создайте новый.

### Шаг 7. Ручная проверка перед отключением Python-клиента

Пройдите по списку и отметьте результат:

- [ ] Вход и выход из аккаунта, смена пароля.
- [ ] Лобби и чат.
- [ ] Создание персонажа, просмотр карточки профессии.
- [ ] Tower: карта мира, движение, бой с мобом, смерть и возрождение, награда.
- [ ] Economy: город, склад, производство, замок, конюшня, рейсы.
- [ ] Deck: вход в мир, таверна, колода и библиотека.
- [ ] Front Line: драфт героя, отсчёт, волна, таверна (если доступна карта Front Line).
- [ ] Редактор карт (только модератор): сохранить черновик, открыть, опубликовать на тестовом мире.
- [ ] Таверна и присутствие AFK: найти аналог в Godot или отметить как не перенесённое.

Тестовые проверки выполняйте на тестовом мире, не на рабочем.

### Шаг 8. Автоматические тесты Godot

Из папки проекта:


Успешный прогон выводит строку вида `tower_entity_smoke_test: OK (212 checks)`. Так можно проверить любую сцену из `godot_client/tests/` (всего 103 файла `*.tscn`).

Известные падения на момент передачи, не связанные с Front Line и бойем:

Часть тестов падает по известным причинам (см. `docs/troubleshooting.md`): тестовая схема не применяет миграции из `server/migrations/central/`, и часть тестов редактора карт не проходит.

### Шаг 10. Вывод Python-клиента из работы

- Не удаляйте `main.py`, `scenes/`, `ui/`, `client/`. Оставьте как резерв.
- Пока шаг 7 не пройден полностью, не переключайте повседневную работу.
- После проверки отметьте в этом документе, какие функции перенесены, и переведите оператора 2 на `godot_client/`.

## 5. Ограничения и известные проблемы

- `/download/client` на сервере отдаёт архив **Python-клиента** (`scripts/build_client_package.py`). Godot-клиента в нём нет. Godot-клиент передаётся через репозиторий или копию папки.
- `RUN_CLIENT.txt` внутри архива указывает адрес `192.168.1.230`. Это адрес конкретной сети, а не настройка проекта. Замените его на нужный адрес, когда будете запускать клиент вручную.
- Front Line в Python-клиенте не работает совсем.
- Версия клиента и протокол задаются в `godot_client/scripts/api_client.gd`. При изменении протокола нужно менять и сервер (`server/build_info.py`), и клиент одновременно.

Скопируйте блок ниже агенту. Перед работой агент должен прочитать файлы, указанные в блоке.

```
Ты помогаешь оператору 2 перевести клиент игры с Python (Pygame) на Godot 4.7.1.

Работай только в локальной папке проекта оператора: <папка-проекта>. Не меняй файлы в других папках.

Сначала прочитай:
- docs/CLIENT_MIGRATION_OPERATOR2.md (этот переход)
- docs/OPERATOR2_HANDOFF.md (состояние кода и механики)
- AGENTS.md (правила проекта, порядок перезапуска серверов)
- godot_client/README.md (сцены Godot-клиента)

Жёсткие правила:
- Не выполняй git commit, git push, git reset --hard, git checkout ., git clean -fd без явного разрешения оператора.
- Не удаляй map_drafts/, данные PostgreSQL, пароли и строки подключения. Секреты не записывай в код и документы.
- Не меняй серверную логику и API ради клиента. Если клиенту нужно новое поле, сначала спроси оператора.
- Перед перезапуском серверов останавливай только точные PID старых процессов. Порядок: центральный сервер (8765), затем миры. Проверяй /health.
- Godot-клиент не пускает, если /api/version сообщает несовместимость. Не обходи эту проверку.

Порядок работы:
1. Выведи git status и git log -3. Если версия кода не та, что нужна, остановись и спроси оператора.
2. Проверь, что Godot 4.7.1 установлен. Запусти один тест через headless-команду из docs/CLIENT_MIGRATION_OPERATOR2.md (шаг 8).
3. Запусти центральный сервер и проверь /health и /api/version?app=client&version=1.0.0&protocol=1.
4. Пройди чеклист шага 7 в docs/CLIENT_MIGRATION_OPERATOR2.md. Для каждого пункта запиши: что проверено, что сработало, что нет.
5. Не отключай Python-клиент. Список функций, которые нельзя перенести, верни оператору.

В отчёте укажи точно: какие команды выполнены, что вывели, что не проверено. Не пиши «всё работает», если не запускал проверку.
```
