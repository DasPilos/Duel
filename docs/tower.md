# Tower — режим Tower Defense

## Цель режима

Игроки защищают башню от волн мобов. Условия победы, устройство волн, параметры башни,
командные правила и начисление очков пока требуют отдельной спецификации; этот документ
не считает их реализованными.

## Граница режима

- Миры, персонажи, прогресс, предметы и сессии принадлежат только схеме PostgreSQL `tower`.
- Серверный запуск: `python -m tower.server.main`; API-маршруты режима перечислены в
  `tower/server/api.py`.
- Серверная логика боевого мира принадлежит `tower/server/world_mobs.py`; общий
  `server.main` предоставляет только HTTP/процессные основы, а Tower подключает свою
  реализацию через собственный entrypoint.
- Tower не обслуживает экономические API города и производства (`/api/buildings/...`,
  `/api/forge/...`, `/api/castle/...`, передвижение жителей и конвоев).
- Правила боя, мобов, волн и башни должны принадлежать Tower. Нельзя брать механику
  выпадения ресурсов из Economy или правила пошагового боя из Deck без отдельного
  решения владельца каждого режима.
- Общие аккаунт и лобби принадлежат центральному серверу. Центральный сервер выдаёт
  выбранному миру ограниченную сессию; сервер мира не регистрирует аккаунты и не принимает
  пароль игрока.

## Графика

Клиентские изображения и каталог тайлов общие для всех режимов. Общность изображения
не означает общность механики: тайл, объект или моб получает поведение только в правилах
Tower. Оператор Tower настраивает его поведение отдельно, не меняя правила Economy или
Deck.

## Текущее состояние реализации

- Есть отдельный entrypoint, схема данных и набор разрешённых API-маршрутов Tower.
- Существующий боевой runtime пока не реализует Tower Defense с волнами; не описывайте
  его как готовый режим защиты башни.
- Очки рейтинга Tower и очки вселенной — заглушка: начисление, таблицы и отображение
  пока не реализованы.
