# Колода: версия, запуск и проверка

Документ для обоих операторов. Описывает ветку `kaloda` в репозитории `DasPilos/Duel`: как скачать, запустить и проверить Колоду, а также как Оператор 1 может попробовать свою часть игры в этой же ветке.

## 1. Что это

Колода — отдельная игра, выделенная из общего проекта. Общими остаются только две вещи:

- **сервер-база данных PostgreSQL** (учётные записи, сессии, список миров);
- **лобби**: экран «Миры», где игрок выбирает, куда зайти.

Всё игровое у Колоды своё: персонажи, предметы, колоды, бои, таверна, гильдия, магазины, подземелье, чат и карта первого мира. Оператор 1 играет в открытый мир со своей механикой боя; Колода играет в карточные бои на карте с кобольдами, скелетами и подземельем. Таблицы Колоды лежат в отдельной схеме PostgreSQL (`kaloda`), таблицы Оператора 1 — в `public`. Миграции Колоды не меняют таблицы Оператора 1.

Ветка основана на коммите `7282864` (`origin/operator1-current-2026-10-30`). Не берите за основу `origin/main`: он устарел.

## 3. Требования

- Windows 10/11 или Linux, Python 3.13.
- PostgreSQL 15 или новее.
- Пакеты из `requirements.txt`: `pygame`, `psycopg[binary,pool]`, `websockets`, `opencv-python-headless`, `tzdata`.

```powershell
python -m pip install -r requirements.txt
```

## 4. База данных

Схема общая для двух игр, поэтому порядок такой:

1. **Создать базу `game`** (один раз, от суперпользователя PostgreSQL):
   ```powershell
   psql -U postgres -h 127.0.0.1 -f deploy/postgres/create_database.sql
   ```
   Скрипт попросит задать пароль пользователя `game`.

2. **Пароль хранить только в `pgpass`**, не в коде и не в переменных окружения. Файл: `%APPDATA%\postgresql\pgpass.conf` (Windows) или `~/.pgpass` (Linux). Строка:
   ```
   127.0.0.1:5432:game:game:ВАШ_ПАРОЛЬ
   ```

3. **Общие таблицы** (`users`, `sessions`, `worlds`) создаёт сервер Оператора 1 при первом запуске, миграциями из его папки `server/migrations/`. Сервер Колоды без них не запустится и сообщит об этом.

4. **Миграции Колоды** применяются при первом запуске сервера мира автоматически, в схему `kaloda`.

5. **Запись о мире Колоды.** Код мира обязан начинаться с `kaloda`, иначе сервер откажется стартовать (защита от запуска не в свой мир). Пример, выберите свободный `id`:
   ```sql
   INSERT INTO public.worlds (id, code, name, status, created_at)
   VALUES (5, 'kaloda1', 'Колода', 'open', extract(epoch FROM now()));
   ```
   Лобби показывает мир, если у него есть `server_url`. Сервер Колоды сам записывает свой адрес при старте и убирает его при остановке.

## 5. Запуск сервера Колоды

Один процесс — один мир. Из корня репозитория:

```powershell
$env:KALODA_WORLD_ID = "5"          # id записи worlds с кодом kaloda…
$env:KALODA_PORT = "8766"           # по умолчанию 8766 (8765 занят сервером Оператора 1)
python -m kaloda.server.main
```

Переменные окружения:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `KALODA_WORLD_ID` | — (обязательна) | Номер мира Колоды в таблице `worlds`. |
| `KALODA_PORT` | `8766` | Порт HTTP-сервера. |
| `KALODA_PUBLIC_URL` | `http://127.0.0.1:<порт>` | Адрес, который увидит лобби. На общем сервере задайте внешний адрес. |
| `KALODA_SCHEMA` | `kaloda` | Схема игровых таблиц. |
| `KALODA_SHARED_SCHEMA` | `public` | Схема общих таблиц `users`, `sessions`, `worlds`. |
| `KALODA_DATA_DIR` | `data/kaloda` | Папка состояния ботов (`bot_state.json`). В git не попадает. |
| `DATABASE_URL` | `postgresql://game@127.0.0.1:5432/game` | Адрес базы. Пароль — только в `pgpass`. |

Проверка, что сервер жив:
```powershell
curl.exe http://127.0.0.1:8766/health        # {"status": "ok"}
```

## 6. Запуск клиента

Клиент входит через лобби Оператора 1 (его сервер, порт 8765). Там игрок выбирает мир:

```powershell
python main.py --online --server http://127.0.0.1:8765
```

- Логин и пароль можно передать флагами `--username`, `--password` или переменными `GAME_USERNAME`, `GAME_PASSWORD`. Без пароля клиент спросит его сам.
- Мир Колоды открывается сценой Колоды (выбор персонажа, карта, таверна). Мир Оператора 1 — его обычным экраном.
- Вход в мир Колоды решает `kaloda/entry.py`: клиент спрашивает у сервера мира `/api/kaloda/info`, и если сервер отвечает `"game": "kaloda"`, открывается Колода.

Если сервер Колоды запущен отдельно, клиент может подключиться к нему напрямую. Тогда лобби не нужно, достаточно указать адрес мира.

## 7. Как играть (первый мир)

1. **Персонаж.** Создайте героя: имя до 15 символов и один из классов (воин, лучник, ассасин, маг, некромант). Новый герой получает 100 монет и стартовые карты класса.
2. **Карта.** Персонаж появляется у кристалла возрождения. Ходите по клавишам или мышью.
3. **Город.** Внутри стен:
   - **Гильдия** — задания за убийства, награды монетами.
   - **Магазин припасов** — зелья и расходники.
   - **Карточная лавка** — карты класса и универсальные карты.
   - **Библиотека** — справочник предметов.
   - **Таверна** — выход на улицу, комната персонажа, задний двор, напитки у хозяина.
4. **Бой с кобольдом** — на поле за стенами. Бой на арене картами, по ходам.
5. **Подземелье** — за воротами, шесть комнат с кобольдами и скелетами. Сундук в последней комнате.
6. **Задний двор** — вызовы других игроков и ботов на бой, групповые бои.
7. **Инвентарь** — клавиша `I` на карте, в таверне и в комнате персонажа.

Клавиши: `Enter` — открыть чат; `Esc` — меню выхода; `I` — рюкзак и карточка персонажа.

## 8. Монеты и цены

Одна валюта — монеты. 1 монета = 1 медная монета из прежних версий. Все цены и награды в монетах.

- Стартовый кошелёк нового героя: **100**.
- Награда гильдии за задание: от 10 (кобольд) до 780 (зачистка подземелья).
- Сундук короля скелетов: **830** монет плюс предметы.
- Продажа карты по редкости: обычная 15, редкая 50, эпическая 150, легендарная 700.
- Эль в таверне: 20.
- Цены карт (примеры): «Ловушка» 300, «Призыв волка» 550, «Божественное исцеление» 75, «Страшная порча» 1100, «Телепорт» 200. Костолом (только в подземелье, эпический) — 250.

Цены карт и предметов задаются в `kaloda/combat/card_database.py` и `kaloda/server/items_database.py`.

## 9. Проверка (тесты)

Тесты создают свои временные схемы (`test_shared_*`, `test_kaloda_*`) и удаляют их после себя. Рабочие схемы не трогают.

```powershell
$env:SDL_VIDEODRIVER = "dummy"
$env:SDL_AUDIODRIVER = "dummy"
$env:PYTHONIOENCODING = "utf-8"
python -m unittest discover -s tests/kaloda -t .
```

Полный прогон занимает около 6 минут. Последний прогон ветки: 531 тест, все проходят.

Линтер:
```powershell
python -m pyflakes kaloda tests\kaloda
```

## 10. Ручная проверка (чек-лист)

- [ ] Сервер Колоды отвечает на `/health` и на `/api/kaloda/info` с токеном.
- [ ] Создаётся персонаж, у него 100 монет.
- [ ] Карта: персонаж ходит, стены держат, ворота открыты.
- [ ] Таверна: вход с улицы, выход на улицу рядом с дверью, комната персонажа, задний двор.
- [ ] Напиток у хозяина: тратятся монеты, растёт здоровье; при полном здоровье — реплика хозяина.
- [ ] Гильдия: задание кобольда, награда 10 монет.
- [ ] Кобольд на поле: бой на арене, победа даёт опыт (`+N опыта`).
- [ ] Карточная лавка: покупка «Ловушки» за 300 монет.
- [ ] Подземелье: вход, первая комната, сундук в шестой.
- [ ] Задний двор: заявка на бой, бот принимает.
- [ ] Инвентарь (`I`): открывается на карте, в таверне и в комнате персонажа, на заднем дворе не открывается.
- [ ] Чат: сообщение доходит, в «Личных» видно только участникам.

## 11. Что Оператор 1 может попробовать

Оператор 1 может скачать эту ветку и проверить:

1. Клонировать репозиторий и переключиться на ветку `kaloda`.
2. Установить зависимости и поднять свой сервер (его инструкции — `docs/server.md` и `docs/README.md` в его ветке).
3. Запустить сервер Колоды по разделу 5 и увидеть мир Колоды в лобби.
4. Зайти в мир Колоды клиентом из раздела 6 и пройти чек-лист из раздела 10.

Оператор 1 может также проверить свой мир, зайдя в него через тот же лобби: мир без префикса `kaloda` открывается обычным экраном Оператора 1.

Обе игры общаются только через лобби и общую базу. Если что-то из общего слома (например, таблицы `users`), это видно сразу у обоих.

## 12. Что не перенесено и известно

- **Редактор карт** для Колоды не перенесён. Редактор в ветке — редактор Оператора 1, он работает только с его сервером.
- **Карта первого мира** задаётся кодом (`kaloda/map_config.py`), а не редактором. Сохранённые карты и публикация миров в Колоде не работают.
- **Зал славы** не перенесён: в исходной версии его не было.
- **Панель колод** в отдельном окне не перенесена: колоды выбираются в карточке персонажа.
- **Журнал боя** («Лог боя») убран из чата.
- **Архив боёв** хранится в базе (таблица `battle_archive`). Бои ботов между собой не архивируются.
- **Открытый мир и механика Оператора 1** в Колоду не входят.
- **Код Оператора 1 в ветке не удалён.** Решение о его судьбе в этой ветке ещё не принято.

## 13. Безопасность

- Пароли не хранятся в коде и в переменных окружения; только в `pgpass`.
- Пароли пользователей хранятся хешем (PBKDF2, 200 000 итераций).
- Токен входа живёт 7 дней.
- Данные ботов (`data/`) и кэши (`__pycache__/`) в git не попадают: см. `.gitignore`.

## 14. Типичные проблемы

- **«Мир WORLD_ID=… не найден»** — записи в `worlds` с таким `id` нет. Проверьте `KALODA_WORLD_ID` и запись в таблице.
- **«Мир … принадлежит не Колоде»** — код мира не начинается с `kaloda`. Исправьте код мира или выберите другой мир.
- **«В схеме public нет общих таблиц»** — сначала запустите сервер Оператора 1 один раз, чтобы создались `users`, `sessions`, `worlds`.
- **Мир Колоды не виден в лобби** — у записи нет `server_url`: сервер Колоды не запущен или не смог записать адрес. Проверьте лог сервера.
- **Ошибка «Сессия недействительна»** — токен истёк или выбран не тот мир. Войдите заново.
- **Русские буквы в консоли выглядят как крякозябры** — задайте `$env:PYTHONIOENCODING = "utf-8"`.
