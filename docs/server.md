# Сервер и общие миры

Авторитетный HTTP-сервер использует PostgreSQL через psycopg 3. Схема обновляется
упорядоченными SQL-миграциями при старте (`server/migrations/`). Персонажи,
население, производственные склады, повозки и бои ограничены `world_id`.

## Запуск сервера

Из корня проекта:

```powershell
python -m server.main
```

Для локальной разработки задайте `HOST=127.0.0.1`, `PORT=8765`, `WORLD_ID=1` и
`DATABASE_URL` на отдельную development-БД. Пароль PostgreSQL хранится в
`pgpass.conf`, не в исходниках. Сервер проверяет `/health` на
`http://127.0.0.1:8765/health`.

## Запуск CLI-клиента

В отдельном окне терминала:

```powershell
python -m client.main
```

CLI-клиент:

1. регистрирует пользователя, если его ещё нет;
2. выполняет вход;
3. создаёт персонажа или загружает существующего;
4. отправляет состояние на сервер;
5. отключается после сохранения.

Pygame-клиент после входа показывает список персонажей. Можно выбрать
существующего героя или создать нового с именем длиной до 15 символов.
После выбора открывается локация «Трактир» с NPC Барменом Картинкой,
правилами игры и переходом к тренировочному бою.

Можно передать параметры без интерактивного ввода:

```powershell
python -m client.main --username testuser --password secret1 --character Воин
```

## Запуск Pygame-клиента с сервером

В отдельном окне после запуска сервера:

```powershell
python main.py --online
```

На титульном экране доступны кнопки «Войти в аккаунт» и «Регистрация».
После выбора режима введите имя пользователя и пароль.
Флажок «Запомнить логин и пароль» автоматически заполнит данные при следующем запуске.
Следующий экран позволит выбрать существующего персонажа или создать нового.
Изменения характеристик и завершённые ходы сохраняются через сервер.
При закрытии окна клиент сохраняет последний snapshot и завершает сессию.

Для предзаполнения формы можно использовать переменные окружения:

```powershell
$env:GAME_USERNAME = "testuser"
$env:GAME_PASSWORD = "secret1"
$env:GAME_CHARACTER = "Воин"
python main.py --online
```

## API

- `GET /health` — проверка доступности;
- `POST /api/register` — регистрация;
- `POST /api/login` — вход и получение Bearer-токена;
- `POST /api/characters` — создание персонажа;
- `GET /api/characters/me` — загрузка персонажа текущего пользователя;
- `GET /api/opponents` — список соперников для заднего двора;
- `GET /api/characters/{id}` — загрузка персонажа по ID;
- `PUT /api/characters/{id}` — сохранение состояния;
- `POST /api/sessions/disconnect` — сохранить состояние и завершить сессию.

Социальные API:

- `POST /api/social/presence` — обновить локацию персонажа;
- `GET /api/social/occupants?location=...` — список персонажей локации;
- `GET /api/social/messages?location=...` — сообщения локации и личные сообщения;
- `POST /api/social/messages` — отправить сообщение;
- `POST /api/social/duel-offers` — предложить поединок;
- `GET /api/social/offers` — получить входящие предложения;
- `POST /api/social/duel-offers/respond` — принять или отклонить предложение.

Город и производство:

- `GET /api/castle/{character_id}/population` — население, занятость рабочих мест,
  пищевой баланс и состояние городского улучшения;
- `POST /api/castle/{character_id}/citizens/{citizen_id}/assign` — назначить только
  свободного жителя на незанятый слот;
- `GET /api/buildings/{building}/{character_id}` — общий склад, открытые ресурсы,
  производственные слоты и состояние улучшений;
- `POST /api/buildings/{building}/{character_id}/storage/withdraw` — взять ресурс
	из общего склада с проверкой доступности и вместимости рюкзака;
- `POST /api/buildings/farm/{character_id}/farm/upgrade` — запустить одно из
	доступных по уровню улучшений фермы;
- `POST /api/buildings/stable/{character_id}/transport/dispatch` — отправить
	повозку; ремонт, износ и обслуживание учитываются сервером;
- `POST /api/buildings/stable/{character_id}/cart/repair` — отремонтировать
	повозку древесиной из общего склада.

## Онлайн и перезапуск

`GET /api/server/status` возвращает количество уникальных активных игроков и
уведомление о запланированном перезапуске. Считаются только активные presence
людей; AFK-записи и боты не учитываются. Клиент показывает счётчик сверху игровых
сцен, кроме боя и открытых городских зданий.

В том же ответе сервер возвращает epoch-время и timezone `Europe/Kyiv`; часы в HUD
не зависят от времени на компьютере клиента. Каждое серверное сообщение чата
содержит `time_text` и отображается с префиксом `HH:MM:SS` перед отправителем.
Таймеры производств и отгрузки рассчитываются сервером от его системного времени;
клиент только уменьшает полученный остаток по монотонным часам.

Запланировать уведомление может только пользователь с ролью `moderator` или
`admin`. По умолчанию сервер предупредит игроков за 3 минуты и после отсчёта
завершится с ненулевым кодом. Для автоматического запуска после этого сервисный
менеджер должен иметь политику перезапуска при ошибке (на Z440 используется
`systemd` `Restart=on-failure`). Выполните на администраторской машине:

```bash
python -m client.main --schedule-restart --server http://<SERVER-IP>:8765
```

CLI запросит логин и пароль; пароль вводится скрыто. Сервер примет команду только
для аккаунта с ролью `moderator` или `admin`. По умолчанию задержка — 3 минуты;
изменить её можно через `--restart-minutes 1..30`. Отменить перезапуск до
истечения таймера:

```bash
python -m client.main --cancel-restart --server http://<SERVER-IP>:8765
```

## Активный UI чата

Встроенный Pygame-чат находится в `ui/chat/` и подключён к Трактиру и Заднему
двору. Компоненты разделены на `ChatPanel`, `ChatHeader`, `ChannelList`,
`MessageList`, `MessageItem`, `MessageInput` и `UnreadBadge`.

Поддерживаются сворачивание панели, общий/личный режим каналов, история,
отправка Enter или кнопкой, список персонажей и popup профиля.

## WebSocket

Для realtime-чата добавлен отдельный необязательный шлюз:

```powershell
python -m server.realtime
```

Он слушает `ws://127.0.0.1:8766` и поддерживает события `chat:history`,
`chat:send` и `chat:message`. Основной Pygame-клиент пока использует HTTP-polling
как fallback, поэтому WebSocket-шлюз запускается отдельным процессом.
Для запуска установите зависимости из `requirements.txt` тем же интерпретатором,
которым запускается сервер.

## Хранилища и состояние мира

- Production и development используют PostgreSQL; не копируйте производственную
	БД или учётные данные на локальную машину.
- `world_id` разделяет миры. Общие склады, жители, маршруты и повозки принадлежат
	фракции внутри мира; инвентарь остаётся персональным.
- Пайплайн производства помещает добычу всех работников, включая игрока, в общий
	склад здания. Личных квот на добычу нет; снятие ограничено уровнем открытия и
	вместимостью рюкзака.
- Миграции применяются сервером при старте под блокировкой; не редактируйте уже
	опубликованные миграции, добавляйте следующую по номеру.
- Для multi-world деплоя запускается отдельный серверный процесс на мир с его
	собственным `WORLD_ID`.
