# Локальный сервер

Проект содержит локальный авторитетный сервер на стандартной библиотеке Python.
Сервер хранит пользователей, сессии и персонажей в SQLite.

## Запуск сервера

Из корня проекта:

```powershell
python -m server.main
```

Сервер слушает `127.0.0.1:8765`.
База создаётся автоматически в `server_data.sqlite3`.

## Запуск CLI-клиента

В отдельном окне терминала:

```powershell
python -m client.main
```

CLI-клиент:

1. регистрирует пользователя, если его ещё нет;
2. выполняет вход;
3. создаёт персонажа или загружает существующего;
4. отправляет состояние на сервер;
5. отключается после сохранения.

Pygame-клиент после входа показывает список персонажей. Можно выбрать
существующего героя или создать нового с именем длиной до 15 символов.
После выбора открывается локация «Трактир» с NPC Барменом Картинкой,
правилами игры и переходом к тренировочному бою.

Можно передать параметры без интерактивного ввода:

```powershell
python -m client.main --username testuser --password secret1 --character Воин
```

## Запуск Pygame-клиента с сервером

В отдельном окне после запуска сервера:

```powershell
python main.py --online
```

На титульном экране доступны кнопки «Войти в аккаунт» и «Регистрация».
После выбора режима введите имя пользователя и пароль.
Флажок «Запомнить логин и пароль» автоматически заполнит данные при следующем запуске.
Следующий экран позволит выбрать существующего персонажа или создать нового.
Изменения характеристик и завершённые ходы сохраняются через сервер.
При закрытии окна клиент сохраняет последний snapshot и завершает сессию.

Для предзаполнения формы можно использовать переменные окружения:

```powershell
$env:GAME_USERNAME = "testuser"
$env:GAME_PASSWORD = "secret1"
$env:GAME_CHARACTER = "Воин"
python main.py --online
```

## API

- `GET /health` — проверка доступности;
- `POST /api/register` — регистрация;
- `POST /api/login` — вход и получение Bearer-токена;
- `POST /api/characters` — создание персонажа;
- `GET /api/characters/me` — загрузка персонажа текущего пользователя;
- `GET /api/opponents` — список соперников для заднего двора;
- `GET /api/characters/{id}` — загрузка персонажа по ID;
- `PUT /api/characters/{id}` — сохранение состояния;
- `POST /api/sessions/disconnect` — сохранить состояние и завершить сессию.

Социальные API:

- `POST /api/social/presence` — обновить локацию персонажа;
- `GET /api/social/occupants?location=...` — список персонажей локации;
- `GET /api/social/messages?location=...` — сообщения локации и личные сообщения;
- `POST /api/social/messages` — отправить сообщение;
- `POST /api/social/duel-offers` — предложить поединок;
- `GET /api/social/offers` — получить входящие предложения;
- `POST /api/social/duel-offers/respond` — принять или отклонить предложение.

## Активный UI чата

Встроенный Pygame-чат находится в `ui/chat/` и подключён к Трактиру и Заднему
двору. Компоненты разделены на `ChatPanel`, `ChatHeader`, `ChannelList`,
`MessageList`, `MessageItem`, `MessageInput` и `UnreadBadge`.

Поддерживаются сворачивание панели, общий/личный режим каналов, история,
отправка Enter или кнопкой, список персонажей и popup профиля.

## WebSocket

Для realtime-чата добавлен отдельный необязательный шлюз:

```powershell
python -m server.realtime
```

Он слушает `ws://127.0.0.1:8766` и поддерживает события `chat:history`,
`chat:send` и `chat:message`. Основной Pygame-клиент пока использует HTTP-polling
как fallback, поэтому WebSocket-шлюз запускается отдельным процессом.
Для запуска установите зависимости из `requirements.txt` тем же интерпретатором,
которым запускается сервер.

## Ограничения текущего этапа

- сервер локальный и слушает только loopback-интерфейс;
- один пользователь может иметь несколько персонажей;
- расчёт боя пока выполняется в Pygame-процессе, а персонаж и его состояние сохраняются сервером;
- сервер пока не синхронизирует бой между несколькими клиентами;
- профиль другого игрока из пула соперников пока используется для локального боя;
- HP игрока восстанавливается в трактире по 5 единиц в секунду;
- бот восстанавливает HP на сервере по 5 единиц в секунду и отказывается от боя до полного восстановления;
- SQLite подходит для разработки, но не для многопользовательского production-сервера.
- история сообщений теперь сохраняется в SQLite;
- присутствие и активные заявки пока хранятся в памяти процесса;
- WebSocket-шлюз требует установки зависимости `websockets` и пока не включён в основной Pygame-цикл.
- сохранённые данные входа хранятся локально в файле `.mini_duel_login.json` в домашней папке пользователя;
- для общего компьютера не включайте флажок запоминания пароля.
