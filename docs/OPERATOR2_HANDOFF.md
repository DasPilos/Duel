# Передача: текущая версия игры и как развести боевые механики по режимам

Документ для второго оператора (боевая система). Описывает версию на этом компьютере, а не старый `origin/main`.

## 1. Какая версия актуальна

- **`origin/main` на GitHub (DasPilos/Duel) устарел.** В нём ещё есть карточный бой: `CLASSES_AND_CARDS.md`, `assets/cards/`, карточные модули. Не берите его за основу.
- **Текущая ветка: `operator2-sync-2026-10-09`.** Это `origin/main` плюс 18 коммитов, в том числе `1a219cc Remove card battle and dead code`. Карточного боя в коде нет.
- **Есть незакоммиченные изменения.** Около двадцати файлов в рабочем дереве, включая удалённые PNG анимаций (`assets/warrior/attack/...`, `assets/mobs/skeleton.png`). Пока их не закоммитили, опирайтесь на рабочее дерево, а не на историю. Решение, что коммитить, принимает владелец проекта.

## 2. Как устроена игра сейчас

- **Один мир = один процесс сервера** (`server/main.py`) с `WORLD_ID` и `PORT`. Все миры работают на одной базе PostgreSQL. Таблица `worlds` хранит `id`, `code`, `name`, `mode`, `server_url`, `test_only`.
- **Бой только в реальном времени на карте мира.** Клиент (`scenes/world_map_scene.py`) шлёт намерения (позицию, цель удара, рывок) в `POST /api/world/sync`. Сервер (`server/world_mobs.py`) проверяет их, считает удар, урон, смерть, награды и возрождение, и отвечает снимком мира.
- **Мобы — бесы из редактора карт.** Каталог видов в `core/npc_catalog.py`: 15 видов (красные, зелёные, синие; каждый со своим набором экипировки). Листы спрайтов: `assets/NPC/imp_<цвет>_<вид>/`.
- **Настройки мобов по режиму.** `mob_modes/<режим>.json`, чтение и проверка в `core/mob_modes.py`. Там статы, уровень, скорость, замах, откат, агрессия, возрождение, награда, экипировка и зона патруля.
- **Персонаж.** Семь характеристик и профессии (`combat/character_stats.py`): Warrior, Archer, Assassin, Mage (у мага формулы-заглушки). Уровни и опыт в `combat/progression.py`, рывок в `combat/dash.py`.
- **Формулы боя на карте:** `combat/world_stats.py`. Описание и тесты: `docs/BATTLE_MATH.md`, `tests/test_world_stats.py`.
- **Предметы:** `server/items_database.py` (встроенный `CATALOG` и таблица `items_catalog`). Тип экипировки задаётся полем `equip_slot` (13 слотов), эффекты и бонусы хранятся в JSON (`effects_json`, `bonuses_json`).

## 3. Какие поля предметов реально участвуют в бою

Проверено по коду. Это важно, если вы делаете новые предметы или меняете баланс.

| Поле | Где читается | Статус |
|---|---|---|
| `effects.damage` = [мин, макс] | `combat/weapon_damage.py` → урон оружия в `get_world_base_damage` | работает |
| `bonuses` со статами (strength, agility, …) | `fighter.equipment_stat_modifiers` → эффективные статы | работает |
| `bonuses.hp`, `bonuses.mp` | `get_world_max_hp`, `get_world_max_mana` | работает |
| `block` | `get_block_chance` (через модификаторы) | работает |
| `dodge` | формула уворота читает только ловкость | **не работает** |
| замах, восстановление, скорость передвижения | формулы читают только интуицию, ловкость и переноску | **не работает** |
| `crit`, `anti_crit`, `crit_power`, `anti_dodge`, `magic_damage` | в формулах боя нет | **не работает** |
| `effects.requirements` (уровень и статы) | только редактор карт фильтрует список; сервер при экипировке не проверяет | **не проверяется на сервере** |
| `two_handed` | проверка в `server/items_database.py` (`is_two_handed`) | работает |

Редактор предметов (форма «Новый предмет») сохраняет все поля, но пока действуют только строки «работает».

## 4. Режимы и миры

- **Режим — ключ в `core/game_modes.py`** (`GAME_MODES`). Сейчас есть один режим: `tower` («Башня»).
- **Режим мира — поле `worlds.mode`.** Процесс сервера узнаёт свой режим через `Database.world_mode()` (`server/database.py`). По нему берутся настройки мобов (`_mob_config` в `server/world_mobs.py`).
- **Миры из карт редактора** создаются в `server/map_worlds.py` (`create_test_world`, `start_world`). Каждый мир — отдельный процесс на свободном порту из диапазона 8800–8900.
- **Правило проекта:** каждое чтение и запись, относящиеся к миру, содержит `world_id`. Сессии тоже привязаны к миру (`sessions.world_id`).

## 5. Как развести режим второго оператора

Цель: режим живёт на том же сервере и в той же базе, но его бой развивается отдельно. Пункты по порядку.

1. **Зарегистрируйте режим** в `core/game_modes.py`: новый ключ и название. Не меняйте ключ `tower`.
2. **Заведите настройки мобов** в `mob_modes/<ключ>.json`. Не редактируйте `tower.json` ради своего режима.
3. **Выбирайте движок боя по режиму.** В `server/world_mobs.py` (класс `WorldService`) добавьте диспетчер по `self._database.world_mode()`. Для `tower` оставьте текущий код. Для своего режима подключайте свой модуль, например `combat/modes/<ключ>/`.
4. **Не меняйте общие формулы под свой режим.** Функции в `combat/world_stats.py` используются `tower`. Добавляйте новые функции рядом, а старые не трогайте. Для каждого изменения нужен детерминированный тест (с зафиксированным генератором случайных чисел), как написано в `CONTRIBUTING.md`.
5. **Клиент.** Ветку по режиму добавьте в `scenes/world_map_scene.py` или выносите отдельную сцену. Снимок мира (ответ `/api/world/sync`) меняйте только совместимо: поля, которые читает клиент `tower`, должны остаться.
6. **Предметы.** Новые ключи `effects` читает только ваш движок. Смысл существующих ключей (`damage`, `block`, статы и `hp`/`mp` в `bonuses`) общий: их нельзя менять молча. Отдельный баланс по режимам потребует поля с режимами у предмета. Этого пока нет, это предложение.
7. **Персонаж и статы общие.** Изменения в `combat/character_stats.py`, `combat/fighter.py` и `combat/progression.py` затрагивают все режимы. Согласуйте их или переведите на параметры режима.
8. **Миграции.** Схема меняется только новыми файлами в `server/migrations/`. Применённые миграции не редактируем.
9. **Перезапуск серверов.** После изменений в `server/`, `core/` и `combat/` перезапускайте процессы миров (`AGENTS.md`). Иначе мир работает со старым кодом.

## 6. Что нельзя трогать без согласования

- Формулы и настройки режима `tower` (`combat/world_stats.py`, `mob_modes/tower.json`, `docs/BATTLE_MATH.md`).
- Встроенные предметы `CATALOG` (id 1–93). Предметы, созданные в редакторе, получают id от 1000.
- Общие персонажные формулы (п. 5.7).
- Уже применённые миграции.

## 7. Известные проблемы на момент передачи

- Падают тесты редактора карт: `test_map_editor*`, `test_map_editor_seed`, часть `test_map_editor_state`. В каталоге тайлов нет `grass_1` и `bridge_horizontal`. К бою не относятся, появились до текущей работы.
- Маг: формулы-заглушки.
- Сервер не проверяет требования экипировки при надевании.
- Поля предметов из п. 3 со статусом «не работает» сохраняются, но в бою не действуют.
- Незакоммиченные изменения (см. п. 1).
