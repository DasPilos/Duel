# Архитектура проекта

## Общая схема

main.py
   |
   v
DuelScene
   |
   +--> combat.fighter.Fighter
   +--> combat.battle.Battle
   +--> combat.zones.ZONES
   +--> combat.comments
   |
   +--> ui.layout.DuelLayout
   +--> ui.duel_renderer.DuelRenderer
             |
             +--> ui.hud
             +--> ui.sprite_loader.FighterSprite

## `main.py`

Точка входа приложения.

Функции:

- инициализация Pygame;
- создание окна;
- создание игрового цикла;
- обработка закрытия окна;
- передача событий сцене;
- вызов обновления и отрисовки.

Параметры окна:

- ширина: `1920`;
- высота: `1080`;
- частота обновления: `60 FPS`.

`main.py` создаёт `DuelScene` и не содержит правил боя.

## `core/settings.py`

Содержит все константы проекта, используемые остальными модулями:

- имена и размеры шрифтов (`FONT_NAME`, `FONT_SIZE`, `SMALL_FONT_SIZE`, `BIG_FONT_SIZE`, `COMMENT_FONT_SIZE`);
- тайминги фаз расчёта хода (`RESOLVE_CALC_TIME`, `RESOLVE_COMMENTS_TIME`, `RESOLVE_END_TIME`);
- цвета логов и урона (`ENEMY_HIT_LOG_COLOR`, `BOTH_HIT_LOG_COLOR`, `PLAYER_LOG_COLOR`, `NO_HIT_LOG_COLOR`, `DAMAGE_COLOR`, `NO_DAMAGE_COLOR`);
- координаты и размеры элементов интерфейса, используемые `ui.layout.DuelLayout` (позиции зон `ZONE_Y`, прямоугольники кнопок атаки/защиты, кнопка подтверждения, кнопка нового боя, позиции панелей бойцов, заголовков, оверлея, логов, комментариев, всплывающего текста).

Модуль не содержит логики — только значения.

## `combat/fighter.py`

Содержит класс `Fighter`.

Класс отвечает за:

- имя бойца;
- уровень;
- HP и MP;
- атаку и защиту;
- XP;
- получение урона;
- проверку смерти;
- начисление опыта;
- повышение уровня.

Модуль не зависит от Pygame.

## `combat/zones.py`

Содержит словарь `ZONES`.

Ключи зон:

- `head`;
- `body`;
- `waist`;
- `thigh`;
- `shin`.

Значения словаря — русские названия зон, используемые интерфейсом и боевыми логами.

## `combat/battle.py`

Содержит класс `Battle`.

Класс отвечает за:

- игроков боя;
- номер хода;
- выбранные зоны игрока;
- случайный выбор зон противника;
- определение блокировок;
- расчёт урона с учётом бросков `2d6`, серий попаданий и случайного множителя;
- запись истории ходов (последние 4);
- применение урона;
- выдачу XP и попытку левел-апа после победы игрока.

`Battle` не импортирует Pygame и не занимается интерфейсом.

## `combat/comments.py`

Содержит словари текстовых комментариев:

- `ATTACK_COMMENTS` — комментарии атак игрока, индексируются зоной атаки и результатом попадания;
- `DEFENSE_COMMENTS` — комментарии защиты от атаки противника, индексируются результатом блокировки.

Выбор конкретного текста и подстановка деталей (урон, серия, кубики, множитель) выполняется в `DuelScene`.

## `scenes/duel_scene.py`

Содержит класс `DuelScene`.

Сцена является связующим слоем между логикой боя и интерфейсом.

Она отвечает за:

- создание бойцов и объекта `Battle`;
- обработку мыши и клавиатуры;
- состояние текущей фазы (`choose` / `resolve` / `result`) и подфаз расчёта (`CALC` / `COMMENTS` / `END`);
- передачу выбора игрока в `Battle`;
- запуск и отображение расчёта хода;
- формирование боевых комментариев с деталями броска и серии;
- создание записей UI-лога и всплывающего урона (`FloatingText`);
- вызов отрисовщика (`DuelRenderer`).

В отличие от `combat`, сцена импортирует Pygame.

## `ui/layout.py`

Содержит класс `DuelLayout`.

Отвечает за:

- построение `pygame.Rect` для кнопок атаки и защиты по каждой зоне из `ZONES`, используя координаты `ZONE_Y`, `ATTACK_BUTTON_RECT`, `DEFENSE_BUTTON_RECT` из `settings`;
- построение кнопок подтверждения хода и нового боя;
- хранение координат панелей бойцов, заголовков, оверлея расчёта хода, журнала действий, комментариев и позиций всплывающего текста — все значения читаются из `core.settings`.

Модуль не содержит игровой логики, только геометрию интерфейса.

## `ui/duel_renderer.py`

Содержит класс `DuelRenderer`.

Отвечает за отрисовку:

- заголовка;
- панелей бойцов (имя, уровень, полосы HP/MP, спрайт или силуэт-фолбэк);
- зоны выбора атаки/защиты и кнопки подтверждения;
- оверлея во время фазы `resolve` (разные заголовки для `CALC`/`COMMENTS`/`END`);
- журнала последних действий противника;
- боевых комментариев по центру экрана;
- экрана результата боя и кнопки нового боя;
- всплывающего урона поверх всего остального.

Отдельная логика расчёта боя в этом модуле отсутствует. Использует `ui.layout.DuelLayout` для всех координат и `ui.sprite_loader.FighterSprite` для отрисовки спрайтов.

## `ui/hud.py`

Содержит визуальные вспомогательные функции:

- `draw_text` — рисует текст;
- `draw_bar` — рисует полосу значения (HP/MP);
- `draw_button` — рисует кнопку, определяет наведение курсора;
- `draw_silhouette` — рисует примитивный силуэт бойца (фолбэк, если спрайт не загружен);
- `update_and_draw_floating_texts` — обновляет позицию/прозрачность и рисует всплывающие тексты.

Также содержит класс `FloatingText` — текст, который движется вверх и постепенно исчезает (`update()`, `draw(screen)`).

Модуль использует Pygame и не принимает решений о правилах боя.

## `ui/sprite_loader.py`

Содержит класс `FighterSprite`.

Отвечает за:

- загрузку PNG-спрайта бойца (например, `assets/fighters/base/fighter.png`);
- отрисовку спрайта по заданным координатам;
- возврат `False` из `draw(...)`, если спрайт не найден или не загружен, что позволяет `DuelRenderer` откатиться на отрисовку силуэта через `draw_silhouette`.

## Поток одного хода

1. Игрок выбирает зону атаки.
2. Игрок выбирает две зоны защиты.
3. Игрок нажимает кнопку подтверждения.
4. `DuelScene` передаёт выбор в `Battle.choose_player_zones(...)`.
5. Сцена переходит в фазу `resolve`, подфаза `CALC`.
6. `Battle.resolve_turn()` рассчитывает ход: зоны противника, блокировки, броски# Архитектура проекта
